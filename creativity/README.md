## 这个目录回答什么

`requirements.md` 提出了三件事：

1. **无感知采集**个人日常工作与生活信息（电脑客户端 + 移动 App）；
2. 上下文**存储在云端**；
3. 任意**无状态 Agent** 配置 MCP 或 Skill 后，**无需用户专门提示**即可按需取到任务相关的上下文。

本目录把这三件事拆成「问题定义 → 采集 → 建模 → 存储与检索 → Agent 接入 → 隐私治理 → 场景走查 → 选型与路线」八块，逐块给出设想、取舍、备选方案与待定问题。目标是让方案可以被讨论、被否决、被替换，而不是给出一个已经写死的答案。

`requirements.md` 没有指定采集方式。发起人后续补充的采集路径假设是「电脑端定时静默截屏 + 移动端每日人工挑选重要截图 + 系统数据（健康/步数/位置）」，已并入 02 / 03 / 04 / 06 / 07 / 08。本目录把它当作**待验证的主假设**，不是定论。

## 核心设计主张（一页速览）

我们把方案收敛到七条主张；每条都在对应文档里展开，并列出被否决的备选：

1. **它不是笔记应用，而是"个人上下文的记忆层"。** 用户不主动写给谁看，系统也不追求记录完整；唯一目标是在 Agent 执行任务的那一刻，把相关背景喂给它。所有取舍以"任务相关召回率"为准，而不是以"记录完整度"为准。
2. **"不用专门提示"必须用三种注入形态覆盖，而不是一个查询接口。** ①会话开始时按任务锚点自动预热；②Agent 主动调用工具按需检索；③后台订阅在上下文变化时提醒。只有第①种才真正满足"用户没提也能拿到"。
3. **任务锚点是召回的入口。** 当前前台应用、正在看的文档/页面、日历事件、最近消息、剪贴板意图共同构成"情境指纹"，检索由它驱动，而不是等用户写 query。
4. **返回物是"上下文包"而不是条目列表。** 包内含时间线、实体、来源引用、置信度与 token 预算裁剪结果，让无状态 Agent 拿到即可用、可引用、可自查。
5. **访问控制从 ACL 升级为"隐私域 + 用途绑定"。** 只判断"这个 Agent 能不能读"不够，还要判断"这次任务用途是否匹配该域的授权用途"。
6. **推荐混合部署：端侧脱敏 + 本地热缓存 + 云端加密冷存与索引。** 纯云隐私风险高，纯本地跨设备与跨 Agent 能力弱。
7. **记忆是双向的：Agent 的任务结果要能写回。** 只读的记忆层每次都要重新推导用户偏好；写回（在授权与用户确认下）才能形成复利。

## 术语表（全目录统一，其他文档直接引用本表）

| 术语 | 英文 | 定义 |
|---|---|---|
| 上下文条目 | Context Item | 记忆层的最小单位，一段可独立检索、可引用、带来源与时间的信息 |
| 上下文事件 | Context Event | 采集端产生的一次原始活动记录（打开文档、发消息、移动位置等） |
| 情境 | Situation | 一段时间内用户所处的活动状态，由任务锚点 + 上下文事件聚类得到 |
| 任务锚点 | Task Anchor | 描述"用户此刻在做什么任务"的指纹，是召回入口 |
| 情境指纹 | Situation Fingerprint | 任务锚点的可匹配表示（应用、文档/URL、实体、参与者、地点、意图文本等信号的组合），检索由它驱动 |
| 上下文包 | Context Bundle | 面向一次 Agent 任务的组装结果：条目 + 时间线 + 实体 + 来源 + 置信度 + token 预算 |
| 采集器 | Collector | 端侧一个具体采集源（如"macOS 前台窗口"、"iOS 日历"） |
| 摄取管道 | Ingest Pipeline | 从原始事件到可检索条目的处理链：清洗 → 归一化 → 切分 → 抽取 → 索引 |
| 上下文图谱 | Context Graph | 人物、项目、文档、地点、事件之间的实体关系网络 |
| 检索编排 | Retrieval Orchestrator | 按任务锚点做混合召回、重排、裁剪与组装 |
| 上下文网关 | Context Gateway | 对外统一入口，负责认证、授权、审计，并暴露为 MCP/Skill/REST |
| 隐私域 | Privacy Domain | 用户划分的数据边界（如个人/工作/家庭），是授权基本单位 |
| 用途绑定 | Purpose Binding | 授权时同时声明"允许用于哪类任务"，访问时校验用途匹配 |
| 敏感度分级 | Sensitivity L0–L3 | L0 公开、L1 一般、L2 私密、L3 极敏感，决定处理与存储位置 |
| 端侧预处理 | On-device Preprocessing | 数据离开设备前完成的脱敏、分级与裁剪 |
| 每日日志 | Daily Log | 按「日期 + 设备」聚合的屏幕/截图解析文档，是文档级引用而非检索最小单位，供抽取关键上下文 |
| 采集分级 | Capture Level | 一条采集源的上行粒度档位：`metadata_only` / `metadata_plus_text` / `metadata_plus_parsed_image` / `full_artifact`，定义见 [02-capture-clients.md](02-capture-clients.md) |
| 记忆写回 | Memory Write-back | Agent 任务结束后把结论/偏好写回记忆层的受控通路 |
| 无状态 Agent | Stateless Agent | 每次会话不携带历史记忆、只能依赖外部检索获得背景的 Agent |

## 文档约定

- 每篇开头是状态行与一句话摘要；`## 待定问题` 集中列出未决事项，不散落在正文。
- 本文件是索引页：以「文档地图」代替各篇的「相关文档」，不设 `## 待定问题`，索引页本身不承载结论。
- 方案用 **建议 / 备选 / 不采用** 三种标签区分，避免读者误把备选当结论。
- 图统一用 Mermaid（GitHub 直接渲染），不引入外部图片依赖。
- 引用业界产品只作方向参照，具体能力以公开资料为准，不代表最终选型。
- 交叉引用使用**相对路径 Markdown 链接**；术语一律引用本文件术语表。
